## 자세한 경과 (히스토리)

### 1단계: 주제와 가설 확정까지

- 처음 조언은 "공동체/소외계층을 다루면 스토리가 좋다"였음. "어려움을 겪는 집단"을 찾다가, 소수집단은 아는 바가 적고 조심스러워서 대신 "흔하지만 동일하게 어려움을 겪는" 특성(난독증, 길치)으로 방향을 바꿈. 본인이 실제로 길치라 "길치"를 최종 선택.
- 길치 × 3D 게임(특히 지도가 불친절한 게임) 조합으로 후보를 다수 브레인스토밍하다가, "청각 신호"로 좁힘.
- 처음엔 "목적지를 안내하는 소리(ON/OFF)"였는데, **"이건 정답을 알려주는 거라 결과가 뻔하다"는 지적을 받고 설계를 크게 바꿈** — 자세한 건 아래 3단계 참고.
- 최종 가설(현재): "3D 공간 탐색에서, 서로 다른 음색을 가진 고정 청각 랜드마크의 개수(0/2/3)는 길찾기 소요 시간과 경로 효율성에 영향을 주며, 이 효과는 길치인 사람일수록 크게 나타난다."
- 길치 측정은 SBSOD 15문항 대신 검증된 4문항 단축판 R-SOD(Jaswal et al., 2025)를 쓰고, 임상용 컷오프(11.5)로 그룹을 나누지 않고 **연속 점수**로 상관관계를 본다 (우리 표본 4~6명엔 임상 컷오프가 안 맞음).

### 2단계: 참고문헌 확정까지

문헌 8개를 (1)측정 도구, (2)가설 직접 지지, (3)변수 통제 세 카테고리로 정리함. 전부 실제 검색·교차확인·가능하면 PMC 전문 확인까지 거침. 특히:
- **Jetzschke et al. (2017)**: 청각 랜드마크는 서로 다른 소리 3개일 때만 위치 애매함이 완전히 풀린다는 걸 인간 실험(N=25)으로 검증한 논문 — 지금 실험 설계(0/2/3, 서로 다른 음색)의 직접적 근거.
- 처음에 넣었던 GPS 습관 논문, 게임훈련 메타분석 2편은 "가설과의 연결이 억지"라고 판단해 뺐음 (이유는 문서의 "확인 과정에서 걸러낸 문헌" 참고). **문헌을 억지로 끼워맞추지 않는 원칙을 지켰다는 게 이 프로젝트에서 반복된 교훈.**

### 3단계: 실험 설계 — 왜 지금 이 형태가 됐는가

1. **1차 시도(목적지 비콘형)**: 목적지에서 소리가 나서 방향을 알려주는 방식으로 먼저 구현함.
2. **문제 제기**: "청각 신호가 길찾기에 영향을 주는가"를 보려는 건데, 이 설계는 사실상 정답을 알려주는 것이라 결과가 무조건 한쪽으로 나올 수밖에 없다는 지적을 받음. → 설계 근본 재검토.
3. **전환**: "고정 청각 랜드마크 + 삼각측량" 방식으로 변경. 목적지 방향은 절대 알려주지 않고, 서로 다른 음색의 고정 소리 3곳(쇳소리/물방울/기계음)을 참가자가 스스로 종합해서 위치를 추론해야 함.
4. **독립변수를 이분법(ON/OFF)에서 3단계(랜드마크 0개/2개/3개)로 확장** — "2개일 때 애매함이 얼마나 남는지"까지 보는 게 Jetzschke et al.(2017)이 안 다룬 부분이라 새로운 기여가 됨.
5. 이 과정에서 참고문헌도 재평가함 (2단계 문서에 반영 완료).

### 실제 구현 (`sim/` 폴더)

빌드 도구 없는 순수 HTML/CSS/JS + Three.js(CDN) + Web Audio API. Node 내장 모듈만 쓰는 `devserver.js`로 로컬 테스트 (`node sim/devserver.js` → `localhost:5173`).

- **`maps.js`**: 미로 1개를 생성해서 회전/반전으로 3종을 만듦(He et al., 2024 기법). 랜드마크 좌표·막다른 길 좌표도 같이 변환되어 난이도가 3개 맵 모두 수학적으로 동일함 — 자동 스크립트(BFS)로 검증 완료.
  - **미로 재설계, 1차: 손으로 다시 그림 (2026-09-14)**: 처음 설계(9x9, 경로 21칸, 분기점 2곳)를 직접 그려보니 갈림길이 너무 적어서, 랜드마크 0개 조건에서 헤매더라도 헤맬 공간 자체가 부족해 랜드마크 개수 효과가 잘 드러나지 않을 위험이 있었음. 13x13(경로 41칸)으로 다시 그렸는데, 손으로 그리다 보면 의도치 않게 지름길(루프)이 생기기 쉬워서 매번 별도 스크립트로 (1) 그래프가 트리 구조인지, (2) BFS 최단경로가 의도한 길이와 일치하는지, (3) 각 막다른 길이 가지 형태로 정상인지를 검증해야 했음.
  - **미로 재설계, 2차: 알고리즘 생성으로 전환 (2026-09-14)**: recursive backtracker(Wikipedia "Maze generation algorithm" 참고)로 전환. 이 알고리즘은 "완전 미로(perfect maze)"를 구조적으로 보장하므로 루프 검증 자체가 불필요해짐. 시드를 고정(`MAZE_SEED=14`, 6x6칸=13x13격자)해서 재현성을 확보했고, 여러 시드를 시험해본 뒤 손그림 버전과 같은 경로 길이(41칸)가 나오는 시드를 채택. 막다른 길 목록도 더 이상 손으로 나열하지 않고 "BFS 최단경로가 아닌 모든 열린 칸"으로 자동 계산하도록 바꿈.
  - 미로가 커지면서 `TRIAL_TIMEOUT_SEC`(150→420초), `LANDMARK_MAX_DISTANCE`(60→90)도 함께 조정.
  - 벽 통과 시 소리 감쇠(occlusion)는 추천받았으나, Jetzschke et al.(2017)의 원 실험 방식에 없는 새로운 변수를 얹는 것이고 구현 난이도(라인캐스팅+필터)도 있어 지금은 보류. 브라우저 테스트·실제 데이터 수집을 먼저 진행한 뒤 여유가 되면 검토.
- **`survey.js`**: R-SOD 4문항, 역채점 포함 채점 로직.
- **`audio.js`**: `LandmarkAudio` 클래스. PannerNode(HRTF)로 3개 랜드마크를 미로 전역에서 들리게 배치. 시행별로 0/2/3개 중 몇 개를 켤지 외부에서 지정.
  - **근접 확인 효과 추가 (2026-09-14)**: 랜드마크 위치를 화면에 시각적으로 표시할지 논의했으나, 시야를 안개+무늬없는 벽으로 차단하고 청각 채널만으로 위치를 추론하게 하는 게 이 실험의 핵심 조작이라 시각 표시는 배제. 대신 랜드마크에 가까워질수록 해당 소리에 트레몰로(떨림) 효과가 커지는 순수 청각 피드백을 추가해, 실험 순수성을 지키면서도 "가까워지고 있다"는 확인은 가능하게 함.
  - **첫 실사용 테스트 피드백 반영 (2026-09-14)**: 기계음(허밍)이 다른 두 소리보다 유난히 크게 들린다는 피드백 — 쇳소리·물방울은 짧게 끊어 재생(듀티 15~20%)이라 순간 최대음량이 커도 체감 음량은 낮은데, 허밍은 끊김 없이 계속 울려 같은 최대음량이어도 훨씬 거슬리게 들림. 허밍 게인을 0.12→0.05로 낮춤.
  - **사운드 팩 전면 재설계 (2026-09-14)**: 위 게인 조정만으로는 "웅웅 소리가 혼자 튀어서 뭔가 있는 것 같은 착각을 준다"는 문제가 근본적으로 안 풀린다고 판단, 세 랜드마크를 저/중/고 주파수대로 명확히 분리하고(저주파=양쪽 귀 도달시간차, 고주파=귓바퀴 스펙트럼 왜곡으로 방향 판단 메커니즘이 달라 삼각측량에 유리) 전부 "짧게 울리고 끊기는" 방식으로 통일함. 0번(목재 펄스, 300/440Hz, 1.2초 간격), 1번(물방울 아르페지오, 900/1300/1900Hz 상향 3음, 1.8초 간격), 2번(금속 차임, 4200~7900Hz 배음 4개, 1.8초 여운, 2.5초 간격). 재생 간격을 서로 배수 관계가 아니게 잡아 세 소리가 주기적으로 겹쳐 마스킹되는 걸 줄임. 진짜 컨볼루션 리버브는 오디오 자산 없이 못 쓰므로, 배음을 여러 개 겹쳐 길게 감쇠시키는 방식으로 "긴 잔향" 느낌만 흉내냄.
  - **금속 차임 귀 아픔 조정 (2026-09-14)**: "귀가 좀 아프다"는 피드백. 최상단 배음을 7900Hz→6300Hz로 낮추고(3200~6300Hz대로 전체 하향), 공격(attack)을 0.01초→0.035초로 늘려 뾰족한 스파이크 대신 완만하게 퍼지게 했으며, 전체 게인도 낮춤. 고음역이라는 성격(귓바퀴 스펙트럼 왜곡으로 방향 판단에 유리)은 유지하되 가장 자극적인 최상단 대역만 걷어냄.
  - 이전엔 2번(기계음)만 끊김없이 계속 재생돼서, "랜드마크 2개" 조건에서 2번이 빠질 때와 0·1번이 빠질 때가 서로 다른 종류의 변화(끊김없는 소리의 유무 자체)였던 비대칭 문제도 이번에 같이 해소됨 — 셋 다 펄스형이라 "몇 개가 꺼지는지"만 순수하게 비교 가능해짐.
- **`trial.js`**: 3D 씬(안개+무늬없는 벽), WASD+포인터락 이동, 충돌판정, 소요시간·이동거리·경로효율성(최단경로 대비)·재정향시간(멈춰서 시선 돌린 시간)·막다른 길 진입 횟수를 자동 기록.
  - **버그 수정 이력**: 원래 매 시행마다 렌더러를 새로 만들고 버렸더니 연습→본시행 전환 시 화면이 멈추는 문제가 있었음. 렌더러를 세션당 하나만 만들어 재사용하도록 고침 (`getSharedRenderer`).
  - **밝기 조정 (2026-09-14)**: 첫 실사용 테스트에서 "전체적으로 너무 어둡다"는 피드백. 안개 거리(`FOG_NEAR`/`FOG_FAR`, 몇 칸 앞까지 보이는지)는 시각 정보를 통제하는 실험 조작이라 유지하되, 안개·바닥·천장의 색 자체(얼마나 어두운 톤이냐)는 실험 내용과 무관한 부분이라 전반적으로 밝게 조정(천장을 가장 밝게 잡아 "하늘"처럼 보이게 함). 두 차례에 걸쳐 밝힘.
  - **목적지 시각 표시 추가 (2026-09-14)**: "도착지점이 도착지점인 게 표시돼야 한다"는 피드백 — 원래는 목적지 반경(1.2unit) 안에 들어오면 아무 표시 없이 곧바로 시행이 종료돼서, 참가자가 "내가 도착한 건지" 직접 눈으로 확인할 수 없었음. 목적지 위치에 밝은 금색 구체(살짝 위아래로 흔들림)를 추가함. 랜드마크와 달리 이건 "정답 위치를 미리 알려주는" 게 아니라 안개 범위(약 2칸) 안에 들어와야만 보여서, 멀리서 미리 보고 찾아갈 수는 없음 — 도착 확인용일 뿐 방향 힌트는 아님.
- **`main.js`**: 화면 흐름 전체(시작→설문→안내→소리 미리 듣기→워밍업→본시행 3회→결과 다운로드). 참가자 슬롯(1~6번)을 `localStorage`로 자동 순환시켜 카운터밸런싱 표(`config.js`)에서 순서를 자동 배정.
  - **워밍업 맵 분리 (2026-09-14)**: 원래 워밍업이 본시행 맵(MAPS[0], 경로 41칸)을 그대로 썼는데, "연습이 과하게 어렵다"는 피드백을 받음. 워밍업의 목적은 조작·랜드마크 소리 익히기이지 본시행 수준의 길찾기 난이도를 미리 겪게 하려는 게 아니므로, 경로 8칸짜리 짧고 쉬운 전용 맵(`WARMUP_MAP`, `maps.js`)으로 분리함. 랜드마크는 여전히 경로에서 멀리 떨어뜨려 소리 방향 익히는 연습은 유지.
  - **"소리 미리 듣기" 화면 추가 (2026-09-14)**: "처음 테스트하는 사람은 소리만 듣고 무슨 뜻인지 감을 못 잡을 것"이라는 피드백 — 이게 본시행 중 재정향시간(reorientationSec)에 잡음으로 섞일 수 있다는 우려(청각 랜드마크 개수 때문이 아니라 "이 소리가 뭔지 처음 알아가는 중"이라 멈춰 서 있는 경우)와도 연결됨. 안내 화면과 워밍업 사이에 3개 소리를 각각 눌러 미리 들어보는 화면(`screen-soundcheck`)을 추가함. 공간 패닝 없이(방향 정보 없이) 순수 음색 구분 연습만 하도록 `LandmarkAudio.previewOnce(idx)`를 새로 만듦.
  - **"소리 0개도 정상" 안내 추가 (2026-09-14)**: "0/2/3개로 소리 개수가 다르게 나온다는 걸 미리 고지해야 한다"는 피드백. 랜드마크 0개 조건에서 소리가 하나도 안 들리는 게 오류로 오인될 수 있어서, 안내 화면에 "소리가 하나도 안 들리는 시행이 있어도 정상, 고장 아님"을 명시적으로 추가함.
- **데이터 저장**: 백엔드 없음. 참가자가 끝나면 JSON 파일을 다운로드하고, 연구자가 `sim/data/raw/`에 수동으로 모음 (대면/동석 진행을 가정).
