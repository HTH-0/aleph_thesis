## 자세한 경과 (히스토리)

### 1단계: 주제와 가설 확정까지

- 처음 조언은 "공동체/소외계층을 다루면 스토리가 좋다"였음. "어려움을 겪는 집단"을 찾다가, 소수집단은 아는 바가 적고 조심스러워서 대신 "흔하지만 동일하게 어려움을 겪는" 특성(난독증, 길치)으로 방향을 바꿈. 본인이 실제로 길치라 "길치"를 최종 선택.
- 길치 × 3D 게임(특히 지도가 불친절한 게임) 조합으로 후보를 다수 브레인스토밍하다가, "청각 신호"로 좁힘.
- 처음엔 "목적지를 안내하는 소리(ON/OFF)"였는데, **"이건 정답을 알려주는 거라 결과가 뻔하다"는 지적을 받고 설계를 크게 바꿈** — 자세한 건 아래 3단계 참고.
- 최종 가설(현재): "3D 공간 탐색에서, 서로 다른 음색을 가진 고정 청각 랜드마크의 개수(0/2/3)는 길찾기 소요 시간과 경로 효율성에 영향을 주며, 이 효과는 길치인 사람일수록 크게 나타난다."
- 길치 측정은 SBSOD 15문항 대신 검증된 4문항 단축판 R-SOD(Jaswal et al., 2025)를 쓰고, 임상용 컷오프(11.5)로 그룹을 나누지 않고 **연속 점수**로 상관관계를 본다 (우리 표본 4~6명엔 임상 컷오프가 안 맞음).

### 2단계: 참고문헌 확정까지

문헌 8개를 (1)측정 도구, (2)가설 직접 지지, (3)변수 통제 세 카테고리로 정리함. 전부 실제 검색·교차확인·가능하면 PMC 전문 확인까지 거침. 특히:
- **Jetzschke et al. (2017)**: 청각 랜드마크는 서로 다른 소리 3개일 때만 위치 애매함이 완전히 풀린다는 걸 인간 실험(N=25)으로 검증한 논문 — 지금 실험 설계(0/2/3, 서로 다른 음색)의 직접적 근거.
- 처음에 넣었던 GPS 습관 논문, 게임훈련 메타분석 2편은 "가설과의 연결이 억지"라고 판단해 뺐음 (이유는 문서의 "확인 과정에서 걸러낸 문헌" 참고). **문헌을 억지로 끼워맞추지 않는 원칙을 지켰다는 게 이 프로젝트에서 반복된 교훈.**

### 3단계: 실험 설계 — 왜 지금 이 형태가 됐는가

1. **1차 시도(목적지 비콘형)**: 목적지에서 소리가 나서 방향을 알려주는 방식으로 먼저 구현함.
2. **문제 제기**: "청각 신호가 길찾기에 영향을 주는가"를 보려는 건데, 이 설계는 사실상 정답을 알려주는 것이라 결과가 무조건 한쪽으로 나올 수밖에 없다는 지적을 받음. → 설계 근본 재검토.
3. **전환**: "고정 청각 랜드마크 + 삼각측량" 방식으로 변경. 목적지 방향은 절대 알려주지 않고, 서로 다른 음색의 고정 소리 3곳(쇳소리/물방울/기계음)을 참가자가 스스로 종합해서 위치를 추론해야 함.
4. **독립변수를 이분법(ON/OFF)에서 3단계(랜드마크 0개/2개/3개)로 확장** — "2개일 때 애매함이 얼마나 남는지"까지 보는 게 Jetzschke et al.(2017)이 안 다룬 부분이라 새로운 기여가 됨.
5. 이 과정에서 참고문헌도 재평가함 (2단계 문서에 반영 완료).

### 실제 구현 (`sim/` 폴더)

빌드 도구 없는 순수 HTML/CSS/JS + Three.js(CDN) + Web Audio API. Node 내장 모듈만 쓰는 `devserver.js`로 로컬 테스트 (`node sim/devserver.js` → `localhost:5173`).

- **`maps.js`**: 미로 1개를 손으로 설계(경로 21칸, 꺾임 7회, 막다른 길 2곳)하고 회전/반전으로 3종을 만듦(He et al., 2024 기법). 랜드마크 좌표·막다른 길 좌표도 같이 변환되어 난이도가 3개 맵 모두 수학적으로 동일함 — 자동 스크립트(BFS)로 검증 완료.
- **`survey.js`**: R-SOD 4문항, 역채점 포함 채점 로직.
- **`audio.js`**: `LandmarkAudio` 클래스. PannerNode(HRTF)로 3개 랜드마크를 미로 전역에서 들리게 배치. 시행별로 0/2/3개 중 몇 개를 켤지 외부에서 지정.
- **`trial.js`**: 3D 씬(안개+무늬없는 벽), WASD+포인터락 이동, 충돌판정, 소요시간·이동거리·경로효율성(최단경로 대비)·재정향시간(멈춰서 시선 돌린 시간)·막다른 길 진입 횟수를 자동 기록.
  - **버그 수정 이력**: 원래 매 시행마다 렌더러를 새로 만들고 버렸더니 연습→본시행 전환 시 화면이 멈추는 문제가 있었음. 렌더러를 세션당 하나만 만들어 재사용하도록 고침 (`getSharedRenderer`).
- **`main.js`**: 화면 흐름 전체(시작→설문→안내→워밍업→본시행 3회→결과 다운로드). 참가자 슬롯(1~6번)을 `localStorage`로 자동 순환시켜 카운터밸런싱 표(`config.js`)에서 순서를 자동 배정.
- **데이터 저장**: 백엔드 없음. 참가자가 끝나면 JSON 파일을 다운로드하고, 연구자가 `sim/data/raw/`에 수동으로 모음 (대면/동석 진행을 가정).
