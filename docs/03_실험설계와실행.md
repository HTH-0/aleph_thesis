# 3단계: 실험 설계와 실행

> 이 문서는 설계·구현 부분을 먼저 정리한 것이다. 원자료·실제 참가자 수 관련 항목(§7)은
> 데이터 수집 후 채운다 — 그 전까지 이 문서는 미완성 상태다.

## 1. 무엇을 바꾸고 무엇을 고정했는가

가설(`docs/01`)을 검증하기 위해 브라우저 기반 3D 시뮬레이터(`sim/`)를 직접 만들어 돌린다.
"직접 돌리는 실험" 방식이며, 공개 데이터를 쓰지 않는다.

### 바뀌는 조건 (독립변수 — 참가자 1인당 3회 각각 다르게 배정)

| 변수 | 값 | 비고 |
|---|---|---|
| 청각 랜드마크 개수 | 0 / 2 / 3 | 시행마다 정확히 하나씩, 총 3회 |
| 맵 | 3종 (map0/1/2) | 기본 미로 1개를 회전(map1)·반전(map2)한 것. 구조적으로 100% 동일한 난이도 |
| 순서(카운터밸런싱) | 참가자별 다름 | §4 참고 |

### 조절변수 (측정만 하고 조작하지 않음)

| 변수 | 측정 방법 |
|---|---|
| 참가자의 길치 정도 | R-SOD 4문항 설문, 연속 점수(4~28)로 사용 — 그룹으로 나누지 않음 |

### 고정한 조건 (통제변수 — 모든 참가자·모든 시행에 동일)

| 항목 | 값 | 위치 |
|---|---|---|
| 이동 방식 | WASD + 마우스 포인터락 | `trial.js` |
| 이동 속도 | 3.5 unit/sec | `config.js: MOVE_SPEED` |
| 시야(안개) | 1~9 unit (약 2칸 앞부터 안 보임) | `config.js: FOG_NEAR/FOG_FAR` |
| 벽·바닥·천장 | 무늬 없는 단색, 조명 없음 | `trial.js` — 시각 랜드마크가 생기지 않도록 |
| 목적지 도착 판정 | 반경 1.2 unit | `config.js: GOAL_RADIUS` |
| 시행 제한시간 | 420초 | `config.js: TRIAL_TIMEOUT_SEC` |

| 랜드마크 거리감쇠 | refDistance 8, rolloff 0.6 (완만하게) | `config.js` |

## 2. 측정하는 값 (종속변수)

`trial.js`의 `runTrial()`이 매 시행 종료 시 자동으로 기록한다 (`sim/main.js`가 JSON으로 취합).

| 필드 | 의미 | 계산 방법 |
|---|---|---|
| `elapsedSec` | 소요 시간(초) | 시작 클릭 ~ 목적지 도달까지 |
| `distance` | 실제 이동 거리(unit) | 매 프레임 이동량 누적 |
| `shortestWorldDistance` | 최단 경로 거리(unit) | BFS(`shortestPathCellCount`)로 계산 |
| `pathEfficiency` | 경로 효율성 | `distance / shortestWorldDistance` (1에 가까울수록 효율적) |
| `reorientationSec` | 재정향 시간(초) | 거의 정지(`REORIENT_MOVE_EPS` 이하) 상태에서 시선만 활발히 돌릴 때(`REORIENT_LOOK_MIN` 이상) 누적 |
| `deadEndEntries` | 막다른 길 진입 횟수 | 막다른 길 칸에 새로 들어간 순간만 카운트 |
| `timedOut` | 420초 초과 여부 | boolean |

참가자 단위로는 이름(닉네임), 참가자 슬롯 번호(1~6), R-SOD 점수(원점수+역채점 반영 총점), 3회 시행 결과 배열이 JSON 하나에 담긴다.

## 3. 미로 설계

- **생성 방식**: recursive backtracker(무작위 깊이우선탐색) 알고리즘으로 6×6칸(=13×13 격자) 완전 미로를 생성. 처음에는 손으로 미로를 그렸으나 갈림길 수가 부족했고, 손그림으로 다시 그릴 때마다 의도치 않게 지름길(루프)이 생기는 문제가 있어 이 알고리즘으로 전환했다. 이 알고리즘은 "완전 미로(루프 없는 트리 구조)"를 구조적으로 보장하므로 별도 학술 인용 없이 채택 가능한 공학적 도구 선택으로 판단함.
- **재현성**: 시드(`MAZE_SEED = 14`)를 고정해서 항상 같은 미로가 나옴. 여러 시드를 시험해 직전 손그림 버전과 같은 경로 길이(41칸)가 나오는 시드를 채택.
- **난이도 통제**: 기본 미로 1개를 90° 회전(map1)·좌우 반전(map2)해서 나머지 2개를 만듦 — He et al.(2024)이 제시한, 회전/반전으로 경로 길이·분기 수가 구조적으로 동일한 맵 여러 개를 만드는 기법. 랜드마크 좌표도 같은 변환을 받아 맵이 바뀌어도 경로와의 상대적 위치 관계가 유지됨.
- **막다른 길 정의**: 완전 미로(트리 구조)이므로 "BFS 최단경로에 포함되지 않는 모든 열린 칸"으로 자동 계산됨(손으로 나열하지 않음).
- **검증**: 임시 Node 스크립트로 (1) 열린 칸 수−1 = 인접한 열린 칸 쌍의 수(=루프 없는 트리 구조), (2) BFS 최단경로가 41칸으로 의도한 길이와 정확히 일치, (3) 회전·반전한 3개 맵 모두 위 두 성질이 동일하게 유지됨을 확인함. 재검증하려면 `maps.js`를 읽어 `MAPS` 배열을 얻은 뒤 위 세 가지를 다시 계산하면 된다.

## 4. 참가자 순서 배정 (카운터밸런싱)

- 참가자는 브라우저 `localStorage`의 순번 카운터로 1~6번을 자동 순환 배정받는다(`main.js: getAssignmentForNextParticipant`).
- `config.js`의 `ASSIGNMENT_TABLE`(6행)이 각 참가자가 3회의 본시행에서 만나는 (맵, 랜드마크 레벨) 순서를 정한다.
- 맵과 레벨 각각 3×3 라틴방진을 독립적으로 두 번 반복해서 구성 — 검증 결과:
  - 1/2/3번째 시행 자리마다 맵 0/1/2가 각각 정확히 2번씩 배정됨
  - 1/2/3번째 시행 자리마다 레벨 0/2/3도 각각 정확히 2번씩 배정됨
  - 맵 하나가 특정 레벨 하나에만 고정되지 않음
  - (초기 버전에 map1이 항상 2번째 자리에만 오는 결함이 있어 재설계함 — §9 참고)
- 랜드마크 2개 조건에서 어떤 랜드마크를 뺄지는 `LEVEL2_DROP_INDEX_BY_SLOT`으로 참가자 슬롯마다 순환시켜, 특정 랜드마크의 위치 효과가 항상 같은 방식으로 섞이지 않게 함.

## 5. 청각 랜드마크 설계

Jetzschke et al.(2017)의 핵심 발견(서로 다른 음색 3개일 때만 위치 애매함이 완전히 풀림)에 따라, 3개 랜드마크를 주파수 대역이 뚜렷이 다른 음색으로 설계했다(`audio.js`).

| 인덱스 | 이름 | 주파수대 | 재생 간격 | 특징 |
|---|---|---|---|---|
| 0 | 목재 펄스 | 저음(300/440Hz) | 1.2초 | 통통거리는 타격음 |
| 1 | 물방울 아르페지오 | 중음(900~1900Hz) | 1.8초 | 상향하는 짧은 음 3개 |
| 2 | 금속 차임 | 고음(3200~6300Hz) | 2.5초 | 배음 4개, 1.8초 여운 |

세 소리 모두 "짧게 울리고 끊기는" 방식으로 통일했다. 초기 버전은 2번(금속 차임 자리)만 끊김없이 계속 재생되는 소리였는데, 그러면 "랜드마크 2개" 조건에서 이 소리가 빠지는 경우와 다른 소리가 빠지는 경우가 서로 다른 종류의 변화(끊김없는 소리의 유무 자체가 바뀜)가 되어버리는 문제가 있어 전부 펄스형으로 통일했다. 재생 간격도 서로 배수 관계가 아니게 잡아(1.2/1.8/2.5초) 세 소리가 주기적으로 겹쳐 마스킹(소리 씹힘)되는 것을 줄였다. 랜드마크는 목적지 방향을 가리키지 않으며, 참가자가 다가갈수록 소리가 떨리는(트레몰로) 청각 근접 피드백만 준다(시각 표시는 청각 채널만으로 위치를 추론하게 한다는 설계 취지에 반해 배제).

## 6. 실행 절차

1. `node sim/devserver.js` 실행 → `http://localhost:5173`
2. 참가자 화면 흐름: 시작(이름 입력, 헤드폰 안내) → R-SOD 설문(4문항) → 안내(조작·랜드마크 설명) → 소리 미리 듣기(3음색 구분 연습, 기록 제외) → 워밍업 1회(쉬운 전용 맵, 기록 제외) → 본시행 3회(맵×레벨 순서는 `ASSIGNMENT_TABLE`이 자동 배정) → 결과 JSON 다운로드
3. 참가자가 다운로드한 JSON 파일을 연구자가 `sim/data/raw/`에 수동으로 모음(대면/동석 진행 가정, 백엔드 없음)

## 8. 재현 방법 (요약)

- 미로: `MAZE_SEED` 고정이라 항상 같은 구조 재현됨. 검증은 §3의 방법대로.
- 문법 오류만 빠르게 보려면 `node --check sim/<file>.js` (각 파일이 `window`/`document`/`THREE` 같은 브라우저 전역을 참조하므로, 문법 검사만 되고 Node에서 직접 실행되지는 않는다).
- 참가자 순서 배정 로직은 `localStorage` 상태에 의존하므로, 브라우저를 초기화(시크릿 창 등)하면 슬롯 1번부터 다시 시작한다.

## 9. 설계를 바꾼 과정 (요약)

시뮬레이터를 구현하고 실제로 브라우저에서 테스트해보며 여러 차례 설계를 수정했다. 무엇을 왜 바꿨는지 요약하면 다음과 같다.

| 변경 | 이전 | 이후 | 이유 요약 |
|---|---|---|---|
| 미로 크기·생성 방식 | 9×9, 손으로 설계(21칸) | 13×13, recursive backtracker로 생성(41칸) | 분기점이 너무 적어 랜드마크 개수 효과가 드러날 공간이 부족했음. 손그림은 루프 검증이 매번 필요해 알고리즘 생성으로 전환 |
| 랜드마크 음색 | 쇳소리/물방울/기계음(허밍만 끊김없음) | 목재펄스/물방울아르페지오/금속차임(전부 펄스형) | 허밍만 끊김없이 재생돼 "2개 조건"에서 어떤 걸 빼는지에 따라 조작이 비대칭이었음 |
| 워밍업 맵 | 본시행 맵과 동일 | 짧고 쉬운 전용 맵 | 워밍업이 과하게 어렵다는 피드백 — 조작·소리 익히기가 목적이지 본시행 난이도 선행 노출이 아님 |
| 안내 단계 | 소리 설명만 텍스트로 | "소리 미리 듣기" 화면 추가 | 처음 듣는 소리를 본시행 중 학습하면 재정향시간에 잡음이 섞일 위험 |
| 화면 밝기 | 어두운 톤(안개색 등) | 전반적으로 밝게 | 시야 거리(실험 통제 변수)와 색의 어두운 정도(실험과 무관)를 분리 — 후자만 조정 |
| `ASSIGNMENT_TABLE` | map1이 항상 2번째 시행 자리에만 고정 | 맵 3종 모두 각 자리에 고르게 분포 | 맵 정체성과 시행 순서가 얽혀 있던 카운터밸런싱 결함 수정 |
